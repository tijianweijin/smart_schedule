# 刻时 Ketime

面向项目的大学生日程软件，本地优先。包含日程表、项目单、成长曲线与待收纳。

设置新增“智能模型选择 → 大模型选择”，支持原 GPT 授权和 DeepSeek API。DeepSeek 的密钥连接、模型更新/强度选择、消息测试及日程助手说明见 [DeepSeek接入说明.md](DeepSeek接入说明.md)。MiniMax/Kimi 目前为明确标注的待接入选项。

Android 1.0 工程、构建与迁移说明见 [android/README.md](android/README.md)。手机内嵌当前界面与全部本机 API，不依赖电脑运行服务。安装包输出到 `android/dist/刻时-Android-1.0.apk`。

## 使用

普通离线功能：直接打开 `ketime _demo_0.1.html` 或 `刻时 小样.html`。两个入口内容一致，请固定使用一个入口以保持浏览器本地数据一致。

北邮课表与教学云作业同步（0.5）：

1. 安装 Python 3.10 或更高版本，无需安装第三方 Python 库。
2. 在 Windows 双击 `start-ketime.cmd`，或运行 `python ketime_server.py`。
3. 页面在 `http://127.0.0.1:8766/` 打开，点击右上角设置齿轮，填写账号、教务密码、教学云密码并保存。以后无需重复填写；同一账号下密码留空表示保留已保存密码，切换账号时需重新填写两种密码。
4. 点击日程表工具栏中的“导入课表”，直接更新当前学期课表；导入后请核对日期、教师和地点。如学校未返回学期起始日期，可在设置中填写第一教学周周一。
5. 在日程页底部点击“导入作业”，直接读取教学云待处理作业并加入待收纳。若学校要求验证码，手动填写后继续。

页面依旧可以离线查看并编辑已导入课程；同步时需要联网。本机服务窗口关闭后，需重新启动才能同步。若端口被占用，可运行 `python ketime_server.py --port 8768`，并固定使用该端口。

页面的界面脚本已内嵌在两个 HTML 入口中，节假日和导入作业按钮不依赖单独 JS 文件的 HTTP 加载。更新 Python 服务代码后，仍需重启服务进程；低于 0.5 的服务不支持本地账号设置，页面会在发送认证信息之前提示重启。

### ChatGPT 连接与测试（服务 0.6）

1. 安装可选授权验证依赖：`python -m pip install -r requirements-chatgpt.txt`。课表、作业及离线功能仍不需要第三方 Python 库。
2. 重启 `start-ketime.cmd`，固定使用原本机地址和端口，避免切换浏览器数据位置。
3. 点击右上角“设置 → ChatGPT 连接与测试 → Continue with ChatGPT”，在 OpenAI 官方页面自行登录并允许使用套餐额度。若浏览器阻止新窗口，使用面板中的登录链接。不需要向刻时填写 ChatGPT 密码或普通 API Key。
4. 授权成功后返回原刻时页面，模型列表会读取当前账户的实际可用模型。选择模型，填写测试消息，点击“发送测试消息”；收到完整文字回复后显示“测试成功”。

服务 0.8 新增“GPT → 版本 → 系列 → 推理强度”的联动选择，例如“GPT → 5.6 → Sol → 中”。菜单直接读取当前账户可见且支持 API 的 GPT 文字模型，以及各模型支持的推理强度；不再固定限制为 Sol＋轻度。首次仍优先 `gpt-6.1-sol → gpt-6-sol → gpt-5.6-sol`，优先低强度；用户可以主动改选 Astra、Terra、Luna 或其他实际可用系列。没有 Sol 时，菜单展示账户可用模型供用户选择。

`node tests/chatgpt-browser.js` 使用模拟回复验证四级选择、强度联动、保存及刷新、按账户隔离、更新目录、失效选择拦截和日程助手共用设置；`node tests/model-settings-live.js --live` 在隔离浏览器中读取真实目录并发送一次 Sol 中强度测试，不保存或覆盖用户模型偏好、不修改日程数据。

模型菜单按版本分组列出全部可用模型，可以直接跨版本选择，版本选择框同步更新。改变版本、模型或强度后自动保存；等待“已生效”提示即可使用，无需另点保存。快速连续选择以最后一次选择为准；保存失败时显示错误、阻止测试发送，并保留“保存模型设置”按钮供重试。设置按 ChatGPT 账户分别加密保存在本机，同时应用于日程助手和测试；刷新、重启、切换回原账户和重新授权后保留。点击“更新模型”重新读取当前账户目录与支持强度，不消耗推理额度，也不覆盖仍有效的选择。若已保存的模型被移除或强度不再支持，调用会停止并提示重新选择，不静默切换模型或强度。模型目录中的专用客户端强度（如自动任务委派）不作为公开 Responses 推理强度发送。高强度通常增加等待时间及额度消耗。

此功能按[官方 ChatGPT 套餐授权流程](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)实现动态客户端注册、PKCE、一次性 state/nonce、签名与身份验证。通过[公开 Responses API](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)调用，始终 `stream: true`、`store: false`。只有收到 `response.completed` 且文字非空才视为成功；回复失败、中断、额度限制或空回复不会冒充测试成功。具体资格及可用模型取决于实际账户授权，不承诺所有 Plus 账户或所有模型可用。

授权文件 `.local/chatgpt.dpapi` 使用 Windows 当前用户级加密，与学校账号文件分开；包含稳定主机标识、账户对应的客户端编号及令牌，原子保存并支持过期刷新。凭据不返回前端、不写入日志、浏览器存储、备份或 Git。设置仅展示账户及连接状态，支持添加、切换账户及退出当前账户。退出尝试撤销远端刷新会话；无法确认撤销时明确提示到 ChatGPT 设置中断开应用。本版本不使用现有 Codex 登录凭据，不拷贝 cookie，不生成或索取普通 API Key。

注册回调的客户端编号在交换授权码之前保存为独立的待验证记录，不作为已验证账户或套餐权限。若交换返回 `invalid_grant`，最多自动发起一次新的 OAuth 请求，复用该编号但使用全新的 state、nonce、PKCE 和授权码；不会重复提交失效授权码，也不会循环重试。再次失败时保留错误，由用户决定重新连接；原有已验证账户不会被覆盖。

测试只发送输入框里的文字，不读取或自动修改日程、项目、课表和作业。消息及回复仅保留于当前页面内存，刷新后清空。测试消耗套餐共享额度；调用时需要联网，纯离线 HTML 不提供 ChatGPT 调用。不要在测试文字中输入密码等敏感信息。

### 旧数据迁移与备份

`file://` 页面与本机 HTTP 页面、不同文件入口或端口的浏览器存储互相独立，数据不会自动迁移。先在原页面点击“右上角设置 → 本地数据备份 / 恢复 → 导出当前数据”，再在新页面恢复备份。恢复会替换当前页面数据；请先备份。备份不包含账号密码，也不会修改服务中保存的账号设置。将 JSON 备份保存在个人位置，不要上传到公开仓库。旧版本数据加载时自动补充课表来源字段，已有项目关联与成长记录继续保留。

## 同步规则

- 当前学期课程按真实教学周、单双周、节次展开为具体日期，具有各自的完成状态。
- 点击后直接导入，按账号、学期、排课编号去重。同一课表重复同步不会创建副本。
- 保留完成状态、颜色、项目/节点关联。学校的教师、教室变化会更新；用户手动修改的名称、日期、时间不会被覆盖。
- 学校取消课程时，保留本地记录并标注“学校已取消”，不自动删除已导入课程；可核对后自行删除。
- 不同账号或学期分别保留。课程默认不关联项目，导入后可自行关联。
- 若学校没有返回学期起始日期，需在设置中填写第一教学周周一。导入后请核对日期。
- 不包含考试、成绩、测验、问卷、作业提交或定时后台同步。

## 今日提醒

日程表星期日期下方有独立的“今日提醒”栏。每个日期点击“＋ 提醒”，填写内容和日期即可保存生日、纪念日等全天事项；点击名称可编辑或更换日期，圆圈可勾选完成，删除前确认。完成项置底。提醒按设备本地自然日期保存，不随自定义日起始时间偏移；切换周次显示对应日期，时间网格滚动时提醒栏固定，多条提醒在栏内滚动。

提醒只在页面显示，不发送系统通知，不生成时间日程或项目任务，不参与重叠检测和项目完成度。数据保存在当前页面的本地存储中，随备份导出和恢复；离线 HTML 入口也可使用。旧数据自动补充空提醒列表。

## 日程时间重叠

两项或更多日程在同一时段发生时，每个日程块仅将交叉时间段标红，其余区域保留原代表色。重叠日程并排显示，可分别编辑或勾选完成；结束时间恰好等于另一项开始时间不算重叠。判断使用实际时间，不使用短日程的最小显示高度。跨日续段、自定义一天起始时间、重复日程和调休后的实际日期均参与判断；停课隐藏的课程不参与。已完成日程仍显示其时间重叠，调整或删除日程后标红自动更新。

## 节假日与调休

日程表工具栏点击“节假日”。每个假期可独立设置启用、名称和包含首尾日期的放假范围，以及是否调休。启用调休后，明确填写“原上课日期 → 补课日期”；只有配置的课程会调至指定日期，其他假期课程停课。补课日已有课程保持不变，请自行核对冲突。

提供 2026 年七个法定节假日日期草案，来自[政府发布的假期安排](https://www.wuhan.gov.cn/zwgk/tzgg/202609/t20260907_2844002.shtml)。学校放假和补课安排可能不同，请按学校通知修改。不会把法定上班日自动推断为某天的课，未核实年份不会伪造预设，可用自定义假期填写。

设置保存前显示停课与调休课程次数并要求确认。规则只作用于北邮同步导入的单次课程，手动日程和自行改成重复的日程不受影响。停课课程从日程表展示和有效任务计数中移除，但原数据、完成状态和项目关联仍保留，关闭或移除规则即可恢复。调休只修改展示日期，课程编号与完成状态不变；重新同步不覆盖本地假期规则。规则也随备份导出和恢复。

## 教学云作业导入

点击“导入作业”后，读取当前学生身份下待处理的作业，直接加入待收纳，展示课程名称、作业标题和截止时间。教学云登录与课表教务登录独立，可能使用不同密码。

按账号和作业来源编号去重。截止时间等来源信息更新，本地勾选及手动改名保留；已收纳到项目 / 日程或已删除的作业不会被重新添加。清空浏览器数据或恢复未包含该来源历史的旧备份后，去重历史也会回退。平台作业消失不会被擅自解释成已完成或删除。

待收纳中的勾选仅是本地状态，不代表教学云已经提交。本功能不会提交、上传文件、修改平台状态或获取测验问卷。作业不自动影响项目完成度，归入项目节点后才遵循既有项目规则。截止时间在待收纳列表中显示；无法解析时显示未提供，不猜测期限。

## 隐私和接口限制

账号、教务密码和教学云密码按用户选择永久保存在本机 `.local/account.dpapi`，使用 [Windows 当前用户级 DPAPI 加密](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)，不保存明文文件，不进入 localStorage、数据备份或日志。通常只能在原电脑、原 Windows 用户下解密；同一 Windows 用户下的其他程序仍可能解密，不能代替系统账号保护。设置再次打开时仅显示账号与密码是否已保存，不返回或回填明文密码。设置中可清除保存的账号密码，清除不影响课程、待收纳和节假日数据。

会话 Cookie、教务 token 和教学云 token 只保留在内存。第三方密码管理器的行为由用户自行控制。后端仅监听 `127.0.0.1`，检查 Host、Origin 和一次启动有效的 CSRF token，拒绝跨站访问。只允许指定静态文件，账号密文不可经静态服务下载，HTTPS 证书验证保持开启，不使用第三方代理。

课程、项目、待收纳及节假日规则保存于本机浏览器，刷新和重新打开后保留；清理浏览器数据可能导致丢失，请定期导出备份。这部分本地存储不加密，不适合共享电脑的无保护账户。

当前使用学校移动教务接口，并非承诺长期稳定的官方开放平台。接口或登录策略变化时可能失效；验证码/二次认证不做绕过。请遵守学校相关使用规定，避免频繁请求。

接口字段参考 [Nemoyuzx/where_to_study](https://github.com/Nemoyuzx/where_to_study)，本项目适配器独立实现，未复制其 GPL 源码。

教学云认证与只读列表协议参考 [byrdocs/bupt-auth](https://github.com/byrdocs/bupt-auth) 及 [YouXam/ucloud](https://github.com/YouXam/ucloud)。同样为独立实现，不使用其公共代理，不向第三方传递凭据。登录准备的 Cookie / execution 仅存在服务进程内存，5 分钟有效、登录尝试一次后销毁，最多保留 8 个准备会话；验证码仅供用户手动填写，不使用 OCR 或外部验证码服务。

## 日程助手

助手先识别本次需要建立的日程数量，再分别提取各项属性，并校验数量与明细一致。已创建卡片和待补充表单统一按日期、开始时间排序，同一时间保留原提及顺序；同一天缺开始时间的项放在当天末尾，缺日期的项放在整批末尾。包含不完整日程时仍展示整批草稿，不遗漏完整项；逐项确认后，本批已创建卡片也按时间排序。重复日程按规则计数，不将每次发生展开为独立日程。

日程表“添加日程”左侧的“日程助手”打开覆盖式聊天界面。粘贴通知或用自然语言描述日程，助手自动提取并补全名称、日期、起止时间、地点、备注、重复周期、执行期限、颜色及项目/节点关联。缺少结束时间等信息时，在回复下方显示预填的“创建日程”表单，用户补充后确认保存，无需在聊天中反复补充。日程必须有起止时间，不引入“仅开始时间”类型。完整有效的一批日程仍会自动写入本机，回复下方卡片可跳转到对应日期。地点和备注也可在普通日程编辑窗口修改。

未写年份的明确月日按设备当前年补全；12月提到1月时默认下一年，用户明确今年/明年/去年或年份时优先使用。明确月日优先于粘贴旧通知里的“今天/明天”，程序提供本地日历计算结果辅助判断，不因缺年份阻止提取。通知里的提前入场时间保留在备注，不误作结束时间。

模型与推理强度使用设置中已保存的选择，首次默认优先 Sol＋低强度。须从 `start-ketime.cmd` 打开的本机页面使用，并先在设置中连接 ChatGPT；会消耗同一套餐共享额度。只向 OpenAI 发送当前对话、本地参考日期时区及项目/节点名称，不发送既有日程全文、待收纳内容或学校凭据。对话仅在当前页面内存，刷新清空；新对话不删除已创建的日程。

每天/每周/每月重复沿用现有发生记录与期限计算，多星期几会拆分为独立每周规则。单次最多50条；不支持或歧义的时间和规则需进一步描述。结构化输出经服务端及页面校验后，整批原子保存；格式错误、关联节点已删除、回复中断或本地存储失败时不会产生部分日程。助手只新建，不擅自编辑/删除现有日程。

`node tests/schedule-assistant-browser.js` 使用虚拟回复验证上述流程。`node tests/schedule-assistant-browser.js --live` 显式使用本机已连接账户进行一次真实 Sol 轻度提取及浏览器端创建/跳转/刷新验证，测试日程仅保存在隔离浏览器上下文，不改用户日常浏览器数据。不要把虚拟测试视为真实接口成功。

`node tests/assistant-drafts-browser.js` 验证预填表单、结束时间必填、项目节点选择和重复日程编辑等；`node tests/assistant-drafts-live.js --live` 用升旗通知及日期确认进行两次真实 Sol 轻度请求，验证不追问年份、缺结束时间展示草稿、填入结束时间后的保存及跳转，测试数据只进入隔离浏览器。

`node tests/assistant-sequence-browser.js` 验证多日程计数、完整与缺信息日程排序、同时间稳定排序、缺日期置底、反向确认后的卡片排序及数量不一致拦截；加 `--live` 用一次真实 Sol 轻度请求验证三项独立活动提取，测试仅使用隔离浏览器。

## 自动测试

```text
python -B -m unittest discover -s tests -v
node --test tests/bupt-import.test.js tests/school-tools.test.js tests/schedule-overlap.test.js tests/daily-reminders.test.js tests/embedded-ui.test.js
```

浏览器回归测试使用虚拟课表、不连接学校。开发环境额外提供 Playwright 与 Chromium 后运行 `node tests/browser-smoke.js`。可通过 `KETIME_PLAYWRIGHT` 指定 Playwright 模块路径、`KETIME_BROWSER` 指定浏览器路径。验证导入、刷新、重复同步、完成状态、课程文字转义、备份与移动端布局。

`tests/browser-live.js` 是显式启用的真实接口端到端验证，需先在运行中的服务保存本人或明确授权账号，再临时设置 `KETIME_LIVE_TEST=1`。测试走一键导入流程，不向浏览器传递已保存密码，使用隔离浏览器，不更改日常浏览器数据，不输出课表或作业原始数据。

`node tests/school-browser.js` 与浏览器冒烟测试共用虚拟服务，验证账号设置、一键导入、节假日保存、去重、删除不复活、完成状态、无明文备份及窄屏界面，不连接学校。

`node tests/ui-startup.js` 模拟所有外部 JS 文件均为 404 和旧版本机服务，验证两个入口仍能打开设置及节假日弹窗，并在发送认证信息前提示重启。`embedded-ui.test.js` 检查内嵌脚本与对应 JS 源文件完全一致；维护界面脚本时需同时更新内嵌版本。

`node tests/schedule-overlap-browser.js` 使用隔离浏览器及虚拟日程，验证精确标红、并排布局、完成与编辑、跨日续段、周边界、自定义日起始、重复日程、停课调休、短日程及移动端键盘操作，不访问学校接口。

`node tests/daily-reminders-browser.js` 验证提醒增删改、日期移动、勾选、周次切换、固定栏、备份恢复、离线入口、窄屏和键盘操作，且不改变时间日程、重叠判断或项目完成度。

`tests/test_chatgpt.py` 使用生成的测试签名和虚拟令牌验证 OAuth、加密、刷新、模型范围、完整流及服务保护，不连接 OpenAI。`node tests/chatgpt-browser.js` 使用虚拟授权和回复验证界面、模型、测试、失败、隐私、退出、窄屏、离线和旧服务提示，同样不消耗套餐额度。真实端到端成功需本人完成官方登录后发送测试，并收到真实完整回复；虚拟测试不等于已验证真实账户可用。

维护界面模块后可运行 `node tools/embed-ui.js`，机械同步全部模块到两个单文件入口，再运行内嵌一致性测试。

不要提交账号密码、会话、真实课表测试数据或个人备份；`.local/`、日志、开发缓存及本机设置已忽略。
