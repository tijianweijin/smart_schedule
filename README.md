# 刻时 Ketime

面向项目的大学生日程软件，本地优先。包含日程表、项目单、成长曲线与待收纳。

## 使用

普通离线功能：直接打开 `ketime _demo_0.1.html` 或 `刻时 小样.html`。两个入口内容一致，请固定使用一个入口以保持浏览器本地数据一致。

北邮课表同步（0.3）：

1. 安装 Python 3.10 或更高版本，无需安装第三方 Python 库。
2. 在 Windows 双击 `start-ketime.cmd`，或运行 `python ketime_server.py`。
3. 页面在 `http://127.0.0.1:8766/` 打开，点击日程表工具栏中的“北邮课表”。
4. 输入教务账号和**教务密码**，获取课表并核对学期开始日期、教师、地点及教学周，确认后导入。

页面依旧可以离线查看并编辑已导入课程；同步时需要联网。本机服务窗口关闭后，需重新启动才能同步。若端口被占用，可运行 `python ketime_server.py --port 8768`，并固定使用该端口。

### 旧数据迁移与备份

`file://` 页面与本机 HTTP 页面、不同文件入口或端口的浏览器存储互相独立，数据不会自动迁移。先在原页面点击“北邮课表 → 本地数据备份 / 恢复 → 导出当前数据”，再在新页面恢复备份。恢复会替换当前页面数据；请先备份。将 JSON 备份保存在个人位置，不要上传到公开仓库。旧版本数据加载时自动补充课表来源字段，已有项目关联与成长记录继续保留。

## 同步规则

- 当前学期课程按真实教学周、单双周、节次展开为具体日期，具有各自的完成状态。
- 每次先预览再导入，按账号、学期、排课编号去重。同一课表重复同步不会创建副本。
- 保留完成状态、颜色、项目/节点关联。学校的教师、教室变化会更新；用户手动修改的名称、日期、时间不会被覆盖。
- 学校取消课程时，默认保留本地记录并标注“学校已取消”。可勾选移除，但已完成、关联项目、手动编辑的记录不会删除。返回数据不完整时禁止移除。
- 不同账号或学期分别保留。课程默认不关联项目，导入后可自行关联。
- 若学校没有返回学期起始日期，需填写第一教学周周一。导入前始终应核对日期。
- 第一版仅支持教务课表，不包含教务云作业、考试、成绩或定时后台同步。

## 隐私和接口限制

账号密码与教务 token 仅用于本次请求，不写入磁盘、localStorage 或日志。浏览器密码输入框不会由应用持久化；第三方密码管理器的行为由用户自行控制。后端仅监听 `127.0.0.1`，检查 Host、Origin 和一次启动有效的 CSRF token，拒绝跨站访问。只允许指定静态文件，HTTPS 证书验证保持开启，不使用第三方代理。

课程数据仅保存于本机浏览器，清理浏览器数据可能导致丢失，请定期导出备份。本地存储不加密，不适合共享电脑的无保护账户。

当前使用学校移动教务接口，并非承诺长期稳定的官方开放平台。接口或登录策略变化时可能失效；验证码/二次认证不做绕过。请遵守学校相关使用规定，避免频繁请求。

接口字段参考 [Nemoyuzx/where_to_study](https://github.com/Nemoyuzx/where_to_study)，本项目适配器独立实现，未复制其 GPL 源码。

## 测试

```text
python -B -m unittest discover -s tests -v
node --test tests/bupt-import.test.js
```

浏览器回归测试使用虚拟课表、不连接学校。开发环境额外提供 Playwright 与 Chromium 后运行 `node tests/browser-smoke.js`。可通过 `KETIME_PLAYWRIGHT` 指定 Playwright 模块路径、`KETIME_BROWSER` 指定浏览器路径。验证导入、刷新、重复同步、完成状态、课程文字转义、备份与移动端布局。

`tests/browser-live.js` 是显式启用的真实接口端到端验证，凭据仅从临时的 `KETIME_TEST_ACCOUNT` / `KETIME_TEST_PASSWORD` 环境变量读取。仅可使用本人或明确授权账号；不要把环境变量赋值写入源码、脚本或版本库。测试使用隔离浏览器，不更改日常浏览器数据，不输出课表原始数据。

不要提交账号密码、会话、真实课表测试数据或个人备份；`.local/`、日志、开发缓存及本机设置已忽略。
